Bien que cette catégorie de vulnérabilité soit connue depuis plus de vingt ans, l’injection SQL apparaît encore régulièrement dans les audits de sécurité et les rapports de violation.

## Points clés

- Une injection SQL se produit lorsque des entrées utilisateur sont concaténées directement dans une requête de base de données au lieu d’être correctement paramétrées.
- Les requêtes paramétrées (instructions préparées) éliminent la grande majorité des risques d’injection SQL et nécessitent très peu de modifications du code.
- Les scanners automatisés détectent de nombreuses failles d’injection SQL, mais les points d’injection liés à la logique métier nécessitent souvent des tests manuels.

## À retenir

L’injection SQL persiste surtout dans le code ancien et les développements précipités — la solution est connue et peu coûteuse depuis des années.
