À mesure que les applications communiquent davantage par API plutôt que par pages web traditionnelles, les vulnérabilités propres aux API forment une catégorie distincte et en expansion.

## Points clés

- Le défaut d'autorisation au niveau des objets — lorsqu'une API ne vérifie pas qu'un utilisateur a le droit d'accéder à un identifiant de ressource donné — reste la vulnérabilité d'API la plus fréquemment relevée lors des audits.
- Une exposition excessive des données se produit lorsqu'une API renvoie davantage de données que nécessaire au client, en comptant sur ce dernier pour les filtrer. Un attaquant peut contourner ce filtrage en appelant directement l'API.
- La limitation du débit des API prévient aussi bien les abus (comme le bourrage d'identifiants) que l'épuisement involontaire des ressources par des clients légitimes mais mal configurés.

## À retenir

La sécurité des API exige la même rigueur que celle des applications web traditionnelles, appliquée à une interface souvent bien moins visible et moins testée.
