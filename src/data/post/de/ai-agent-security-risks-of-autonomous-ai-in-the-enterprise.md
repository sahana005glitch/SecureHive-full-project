Wenn Unternehmen KI-Agenten einsetzen, die tatsächlich handeln können — statt nur Fragen zu beantworten — muss das Sicherheitsmodell für diese Agenten Schritt halten.

## Wichtigste Punkte

- KI-Agenten mit Zugriff auf interne Tools oder APIs sind eine neue Art nicht-menschlicher Identität, für deren Verwaltung herkömmliche IAM-Systeme nicht ausgelegt sind.
- Prompt-Injection-Angriffe können einen KI-Agenten zu unbeabsichtigten Handlungen verleiten, indem sie bösartige Anweisungen in Inhalten verstecken, die der Agent verarbeitet.
- Das Prinzip der geringsten Rechte gilt unmittelbar für KI-Agenten: Ein Agent darf nur auf die Tools und Daten zugreifen, die er für seine Aufgabe benötigt, und auf nichts darüber hinaus.

## Fazit

Bei der Sicherheit von KI-Agenten geht es weniger um eine grundlegend neue Disziplin, sondern vielmehr darum, die Grundlagen von Identitäts- und Zugriffsverwaltung auf eine neue Identitätsklasse anzuwenden.
