Many of the most common vulnerabilities in production software trace back to a small set of well-known, avoidable coding mistakes.

## Key points

- Input validation and output encoding, applied consistently, prevent the large majority of injection-style vulnerabilities (SQL injection, XSS, command injection).
- Principle of least privilege applies to code too — a service or function should run with only the permissions it actually needs to perform its task.
- Dependency management — knowing what libraries are in use and keeping them updated — addresses vulnerabilities introduced by third-party code, not just first-party mistakes.

## The takeaway

Secure coding isn't a separate skill from good coding — most secure coding practices are simply rigorous, careful coding applied consistently.
