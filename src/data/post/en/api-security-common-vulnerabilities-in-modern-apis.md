As applications increasingly communicate through APIs rather than traditional web pages, API-specific vulnerabilities have become a distinct and growing category.

## Key points

- Broken object-level authorization — where an API fails to verify a user should access a specific resource ID — is consistently the most common API vulnerability found in audits.
- Excessive data exposure occurs when an API returns more data than the client needs, relying on the client to filter it, which attackers can bypass by calling the API directly.
- Rate limiting on APIs prevents both abuse (like credential stuffing) and unintentional resource exhaustion from legitimate but poorly-behaved clients.

## The takeaway

API security requires the same rigor as traditional web application security, applied to an interface that often has far less visibility and testing.
